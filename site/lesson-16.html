Buổi 16 · Giao thức ứng dụng

FTP, Email, SSH và các giao thức còn lại

Nhiều ứng dụng cùng dùng TCP hoặc UDP nhưng khác nhau ở bản tin, cách quản lý phiên và bảo mật. Buổi này so sánh chúng và tổng kết hành trình đóng gói dữ liệu qua các tầng.

1. FTP: hai kênh, hai cách mở data

FTP truyền thống có control connection tới TCP/21 để gửi lệnh và nhận mã phản hồi, và data connection riêng cho LIST/RETR/STOR. Trong active mode, server chủ động kết nối từ cổng dữ liệu (thường TCP/20) tới cổng client báo trong lệnh PORT; NAT/firewall phía client dễ chặn kết nối vào. Trong passive mode, server công bố một cổng data tạm thời, client chủ động kết nối tới đó; thường phù hợp NAT phía client hơn nhưng server phải mở dải cổng data và công bố đúng địa chỉ bên ngoài NAT.

Lệnh thường gặp: USER, PASS đăng nhập; LIST liệt kê; RETR tải xuống; STOR tải lên. Reply có mã 3 chữ số: ví dụ 220 sẵn sàng, 331 cần mật khẩu, 226 hoàn tất truyền. FTP gốc để lộ mật khẩu và dữ liệu ở dạng plaintext. FTPS là FTP dùng TLS (implicit hoặc explicit); SFTP là giao thức chuyển file chạy trên SSH, khác hoàn toàn FTP/FTPS.

2. Email: chuyển thư và đọc thư

SMTP chuyển thư từ client tới server hoặc giữa mail server. Một hội thoại giản lược: EHLO (HELO cũ), MAIL FROM:<sender>, RCPT TO:<recipient>, DATA, nội dung kết thúc bằng một dòng dấu chấm, rồi QUIT. Cổng 25 chủ yếu mail server↔server; 587 thường để client nộp thư có xác thực và STARTTLS; 465 dùng implicit TLS cho submission. Cấu hình thật phải theo nhà cung cấp.

IMAP quản lý mailbox trên server, đồng bộ thư mục/trạng thái giữa nhiều thiết bị; thường cổng 143 hoặc 993 khi TLS implicit. POP3 tập trung tải thư về client, đơn giản hơn cho hộp thư một thiết bị; thường cổng 110 hoặc 995 khi TLS implicit. STARTTLS nâng kết nối plaintext hiện có lên TLS sau lệnh thương lượng; implicit TLS bắt tay TLS ngay khi kết nối. Nếu STARTTLS không được bắt buộc/kiểm chứng đúng, có rủi ro bị hạ cấp.

MIME mô tả nhiều phần, charset và attachment để email không chỉ là văn bản ASCII. SPF dùng DNS để công bố server được phép gửi cho domain; DKIM ký một số header/body bằng khóa domain; DMARC yêu cầu căn chỉnh danh tính domain với SPF/DKIM và công bố chính sách/báo cáo. Chúng giúp giảm giả mạo domain nhưng không chứng minh mọi nội dung thư là đáng tin.

3. SSH và một số giao thức khác

SSH thường dùng TCP/22. Client và server trao phiên bản, thuật toán; thực hiện trao đổi khóa để tạo khóa phiên, xác thực host key của server, rồi người dùng xác thực bằng mật khẩu hoặc khóa công khai. Sau đó các channel có thể ghép terminal, truyền file hoặc chuyển tiếp cổng trên cùng kết nối mã hóa. Nếu bỏ qua cảnh báo host key thay đổi, nguy cơ kết nối nhầm máy trung gian tăng.

Port forwarding tạo tunnel: local forwarding đưa cổng máy mình tới đích qua SSH server; remote forwarding mở cổng phía server về dịch vụ máy mình. Tunnel chỉ bảo vệ đoạn bên trong SSH, ứng dụng ở đầu cuối vẫn cần kiểm soát quyền. Telnet thường TCP/23 gửi nội dung và mật khẩu plaintext, nên SSH thay thế cho đăng nhập quản trị từ xa.

5. Tổng kết OSI và đóng gói

Khi ứng dụng gửi dữ liệu, mỗi tầng thêm thông tin điều khiển của mình: ứng dụng tạo Data; TCP thêm header tạo Segment hoặc UDP tạo Datagram; IP thêm header thành Packet; Ethernet thêm header/trailer thành Frame; tầng vật lý truyền Bit. Bên nhận tháo lần lượt các lớp: bit→frame→packet→segment/datagram→data. Router thường thay frame cho chặng mới nhưng giữ gói IP và giảm TTL/Hop Limit.

Ví dụ: Gửi HTTP GET qua HTTPS/TCP/Ethernet: HTTP được TLS mã hóa thành record, TCP chia thành segment, IP định tuyến packet, Ethernet chuyển frame tới router đầu tiên. Khi qua router, MAC nguồn/đích của frame thay đổi; IP nguồn/đích thường giữ nguyên nếu không NAT.

Xem lời giải

SFTP là giao thức chuyển file trên SSH, không phải FTP thêm TLS. FTP thêm TLS là FTPS. SFTP mặc định dùng TCP/22, có thể chạy cổng khác nếu SSH server cấu hình như vậy.

Wireshark: Bắt một phiên SSH hoặc IMAPS của chính bạn. Lọc tcp.port == 22 hoặc tcp.port == 993; tìm TCP handshake rồi gói bắt tay bảo mật, so với Telnet/FTP thử trong lab riêng để thấy plaintext. Với NTP lọc ntp và xem dấu thời gian, stratum; với SNMP lab dùng v3 nếu cần bảo mật.
